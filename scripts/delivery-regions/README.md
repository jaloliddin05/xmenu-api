# Справочник областей для зоны доставки

`build.ts` собирает `src/modules/delivery/regions/uz-regions.json`: 14 областей Узбекистана (ISO 3166-2:UZ), из
которых владелец собирает общую зону доставки заведения (`docs/API.md`, «Общая зона доставки заведения»). В сборку
скрипт не входит; результат коммитится.

```sh
npx ts-node --transpile-only scripts/delivery-regions/build.ts            # берёт скачанное из .cache/
npx ts-node --transpile-only scripts/delivery-regions/build.ts --refresh  # скачивает заново
```

## Источник и лицензия

- OpenStreetMap, отношения границ: `admin_level=4` (области), `UZ-QR` (Каракалпакстан) `admin_level=3`, `UZ-TK`
  (город Ташкент). Id отношений в таблице `REGIONS` в `build.ts`.
- Собранные мультиполигоны: `https://polygons.openstreetmap.fr/get_geojson.py?id=<relation>&params=0` (без
  упрощения). Версии и даты правок отношений: OSM API `relations.json`, пишутся в `source` справочника.
- Лицензия **ODbL 1.0**. Подпись «© OpenStreetMap contributors» (`attribution` в JSON и в `GET /delivery/regions`)
  показывается рядом с картой, где рисуются области. Справочник — производная база данных: распространяется на тех
  же условиях (ODbL), строка лицензии в JSON.
- geoBoundaries (gbOpen UZB ADM1) сравнивался и не взят: он сам сделан из OSM 2017 года, та же ODbL, сильно прорежен.

## Обработка

Справочник собирается только этим скриптом и только с общими границами: граница двух соседних областей — одна дуга
топологии, упрощается один раз, поэтому соседи сходятся точно, без щелей и наложений. Упрощать области по отдельности
нельзя (так было в первой версии справочника: щели и наложения до 150 м).

1. Кольца переводятся в `[lat, lng]` и размыкаются; куски меньше 1 га отбрасываются (пишется предупреждение).
2. В OSM Ташкентская область покрывает город. Скрипт проверяет, что каждое кольцо города лежит строго внутри контура
   области и не пересекает его, и добавляет кольца города в область дырами (even-odd): у дыры те же вершины, что у
   города.
3. Все 14 областей одним слоем идут в `mapshaper` (devDependency): топология по совпадающим вершинам (соседи в OSM
   делят узлы), Дуглас–Пекер на сфере, `-simplify dp variable`: город Ташкент 30 м, остальные области 150 м; у общей
   дуги допуск меньший из областей, которые её используют (граница города и области — 30 м). Пересечения, которые
   появились при упрощении, `mapshaper` чинит сам.
4. Округление до 6 знаков, затем проверки той же функцией, что в API (`src/modules/delivery/domain/geometry.ts`): кольцо
   не пересекает себя и другие кольца области; ни одна исходная точка не дальше допуска (+1 м) от упрощённого контура;
   кольца города совпадают с дырами области (иначе сборка падает). Область с нарушением упрощается заново с половинным
   допуском (вместе с её общими дугами).
5. `bbox` по кольцам. Исходная граница города (6 знаков) пишется в
   `src/modules/delivery/regions/fixtures/uz-tk-osm-border.json` для тестов общей границы; в сборку она не попадает
   (`assets` берёт только `regions/*.json`).

Сырые выгрузки лежат в `.cache/` (не в git). Воспроизвести ту же сборку байт в байт можно только из `.cache/` этой
сборки: `--refresh` скачивает текущие отношения OSM, а старых версий отношений скрипт получить не умеет (версии
отношений записаны в `source` справочника). Обработка детерминирована: те же входы дают тот же файл. Поэтому архив
`.cache/` каждой версии справочника хранится рядом с репозиториями: `data/osm/delivery-regions-cache-<версия>.tar.gz`
в корневом репозитории (распаковать в `scripts/delivery-regions/`, затем запуск без `--refresh`).

Версия справочника `osm-ГГГГ-ММ-ДД` (дата сборки; вторая сборка в тот же день получает `.2`, `.3`…) копируется в каждую
часть зоны вместе с геометрией: пересборка сохранённые зоны не меняет. Проверки результата:
`src/modules/delivery/regions/uz-regions.spec.ts` (в том числе точки в 20 м по обе стороны от исходной границы города и
точки вдоль неё через ~200 м: каждая ровно в одной из UZ-TK / UZ-TO).
