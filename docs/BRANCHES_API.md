# Контракт API филиалов

Фронт загружает филиалы через `src/features/branches/lib/branchesApi.js`.
Пока `NEXT_PUBLIC_BRANCHES_MOCK` не `false`, отдаётся демо-список из
`src/config/tenant.js` в том же формате, что описан ниже. Переключение на
реальный бэкенд — одна переменная окружения, компоненты менять не нужно.

Где используются филиалы: страница «Филиалы» (карта + список), выбор филиала
самовывоза в корзине, филиал по умолчанию в заказе, снимок филиала в заказе.

## Эндпоинт, который нужен клиенту

### `GET /branches`

* **Публичный**: без авторизации — гости смотрят филиалы тоже. Токен, если он
  есть, игнорируется. Тенант — по заголовку `X-Tenant-Id` (id организации, UUID).
* Только активные филиалы (скрытые/закрытые навсегда не отдавать).
* Порядок — как задан в админке (`sortOrder`); первый филиал клиент выбирает
  по умолчанию.
* Ответ `200`, массив (пустой массив — допустим):

```json
[
  {
    "id": "main",
    "title": "Mant 24/7",
    "address": "г. Ташкент, Чиланзарский р-н, ул. Бунёдкор, 12",
    "latitude": 41.2856,
    "longitude": 69.2034,
    "hours": "Круглосуточно",
    "phone": "+998711234567",
    "isOpen": true,
    "opensAt": null,
    "closesAt": "2026-11-11T23:00:00+05:00",
    "status": "open"
  }
]
```

| Поле | Тип | Примечание |
|---|---|---|
| `id` | string | стабильный; именно его клиент шлёт как `branchId` в `POST /orders` |
| `title` | string | название |
| `address` | string | адрес одной строкой |
| `latitude`, `longitude` | number | WGS84; без координат филиал клиент отбросит (не нарисовать на карте) |
| `hours` | string | **готовая строка для показа** («Ежедневно 09:00–23:00»); собирается на сервере из расписания, локализация — по `Accept-Language` |
| `phone` | string \| null | для будущей кнопки «позвонить» |
| `isOpen` | boolean | открыт ли **прямо сейчас** по времени тенанта (Asia/Tashkent); филиал без расписания всегда `false` (`opensAt: null`), заказ в него не принимается. Круглосуточно задаётся явно: `is24h` на всех семи днях |
| `opensAt` | string \| null | когда откроется, если сейчас закрыт: ISO 8601 с датой и поясом филиала, например `"2026-11-11T09:00:00+05:00"`; по дате клиент пишет «сегодня в 09:00» или «завтра в 09:00». `details.opensAt` в `409 branch_closed` в том же формате |
| `closesAt` | string \| null | открытый филиал: когда кончается текущий интервал (ISO 8601 с поясом филиала; у круглосуточного дня полночь), закрытый `null`. Клиент ставит один таймер на этот момент (и на `opensAt` у закрытого) и перечитывает список: «открыт сейчас» не устаревает без опроса |
| `status` | string | причина состояния, по ней фронт выбирает текст (по `hours` причину определять нельзя: `hours` пуст и без расписания, и когда все дни выходные): `open`; `closed_now` (закрыт сейчас, `opensAt` заполнен); `no_schedule` (владелец не указал часы, заказ → `branch_hours_not_set`); `closed_all_days` (расписание есть, но в ближайшие 7 дней открытий нет, `opensAt: null`) |

Кэш: ответ меняется редко, но `isOpen` зависит от времени — рекомендуется
`Cache-Control: public, max-age=60` и `ETag`. Клиент хранит список 5 минут и
обновляет в фоне; при ошибке показывает старый список, а если его нет —
«Не удалось загрузить филиалы» с кнопкой «Повторить».

### Связь с заказами

* `POST /orders` самовывоза принимает `branchId` из этого списка; для доставки филиал выбирает сервер по адресу
  (ближайший открытый, который доставляет на адрес, `API.md`, «Стоимость доставки»). Закрытый филиал →
  `409 branch_closed` с `details.opensAt` (код уже обрабатывается клиентом;
  он ещё и перезагрузит список, чтобы обновить `isOpen`). Филиал без
  расписания → `422 branch_hours_not_set`.
* `isOpen` здесь и проверка в `POST /orders` должны считаться **одной и той
  же функцией**, иначе клиент покажет «открыто», а заказ отклонится.
* Неизвестный/выключенный `branchId` → `422 validation_error`.
* В объекте заказа приходит снимок `branch: { id, title, address }`.

## Что нужно бэкенду для хранения (рекомендация)

```
branches
  id, tenant_id, slug/id, title, address, latitude, longitude, phone,
  is_active, sort_order, timezone, accepts_pickup, accepts_delivery

branch_working_hours            -- расписание по дням недели
  branch_id, weekday (0-6), opens_at, closes_at, is_24h, is_closed

branch_hours_exceptions         -- праздники, ремонт
  branch_id, date, opens_at, closes_at, is_closed

branch_delivery_zone            -- зоны доставки филиала, по порядку (position)
  branch_id, position, polygon, price, min_order, free_from

branch_delivery_distance        -- правило по расстоянию (одно на филиал, необязательное)
  branch_id, base_price, included_km, price_per_km, max_km, min_order, free_from
```

`hours` (строка) и `isOpen/opensAt` вычисляются из этих таблиц. Учесть
ночные смены (закрытие после полуночи) и круглосуточные филиалы.

## Эндпоинты панели ресторана (токен сотрудника) — реализованы

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/branch` | все филиалы, включая скрытые, с расписанием и исключениями |
| POST | `/branch` | создать |
| PATCH | `/branch/:id` | поля, `isActive`, `sortOrder`, `acceptsPickup/Delivery` (`telegramChatId` → 400) |
| PUT | `/branch/:id/working-hours` | расписание целиком (`weekday` 1=пн … 7=вс; `closesAt <= opensAt` — ночная смена) |
| POST | `/branch/:id/exceptions` | исключение на дату `YYYY-MM-DD` (upsert) |
| DELETE | `/branch/:id/exceptions/:exceptionId` | убрать исключение |
| DELETE | `/branch/:id` | удалить; если есть заказы — только скрыть (`isActive=false`) |
| GET/PUT | `/branch/:id/delivery-pricing` | правила цены доставки (зоны и расстояние), PUT заменяет целиком |
| GET | `/branch/:id/delivery-pricing/check?lat=&lng=&subtotal=` | цена от филиала до точки (без учёта часов) |
| POST | `/branch/:id/telegram-chat/code` | одноразовый код привязки чата `{ code, expiresIn: 600, botUsername }` |
| DELETE | `/branch/:id/telegram-chat` | отвязать чат (204) |

Правила, расчёт и ошибки: `API.md`, «Стоимость доставки».

`telegram_chat_id` (в ответе `GET /branch`) — группа, куда уходят заказы этого филиала. Задаётся только привязкой:
код из `POST /branch/:id/telegram-chat/code`, затем `/bind КОД` платформенному боту в самой группе (`API.md`, «Чат филиала»).
`phone` — номер для SMS-эскалации (`+998XXXXXXXXX`). В `PATCH /branch/:id` `phone: null` очищает номер, отсутствие поля его не трогает.
